## Story

**As a** integrante da equipe de desenvolvimento,
**I want** iniciar uma aplicação Java/Spring Boot reproduzível, com Maven Wrapper, estrutura em camadas e health check técnico,
**so that** o trabalho subsequente parta de uma base compilável e coerente com a arquitetura ratificada, sem antecipar regras de produto.

## Objective and Context

Esta é a primeira entrega do [EPIC-1](./epic-1-fundacao-tecnica.md). O repositório ainda não contém código de produção. A story estabelece somente a base Java/Spring e o endpoint técnico de saúde; a persistência PostgreSQL, o Dev Container, a CI e os gates de cobertura pertencem às Stories 1.2 e 1.3.

As fontes aprovam Java 21, Spring Boot 3.x e Maven Wrapper. A versão exata de Spring Boot deve ser estável e compatível com a linha 3.x no momento da implementação, fixada no build e não migrada para Spring Boot 4.x.

## Scope

### In scope

- Maven, Maven Wrapper e aplicação Spring Boot 3.x em Java 21.
- Organização mínima da aplicação como monólito modular em camadas: apresentação/API, aplicação, domínio e infraestrutura.
- Endpoint técnico de health check, preferencialmente pelo Actuator.
- Teste automatizado de inicialização do contexto e resposta do health check.
- Nenhuma regra de negócio ou modelo de domínio.

### Out of scope

- PostgreSQL, JPA, Flyway e Testcontainers (Story 1.2).
- Dev Container/Codespaces, GitHub Actions e JaCoCo (Story 1.3).
- Autenticação funcional, JWT, usuários, autorização de fluxos de negócio ou credenciais locais.
- Reservas, aprovações, regras de agenda, entidades, repositórios ou migrações de domínio.
- Testes ou afirmações de proteção concorrente de reservas.

## Acceptance Criteria

1. **AC1 — Java e build:** dado um ambiente com JDK 21, quando `./mvnw -B verify` for executado, então o projeto compila e os testes definidos na story são executados.
2. **AC2 — Maven Wrapper:** o repositório inclui os arquivos versionáveis necessários do Maven Wrapper e o comando de build funciona sem depender de uma instalação global do Maven.
3. **AC3 — Spring Boot:** a versão estável compatível da linha Spring Boot 3.x fica fixada no build; a aplicação inicializa em teste de contexto.
4. **AC4 — Camadas:** a estrutura estabelece as camadas de apresentação/API, aplicação, domínio e infraestrutura com dependências na direção permitida pelo ADR-001; não cria módulos de domínio sem consumidor nem funcionalidades de negócio.
5. **AC5 — Health check:** o endpoint técnico responde com sucesso e estado `UP` em teste automatizado, sem expor detalhes, credenciais ou informações de configuração.
6. **AC6 — Segurança sem autenticação funcional:** a base não cria login, emissão/validação funcional de JWT, usuário padrão ou fluxo de autorização de negócio; o endpoint técnico continua testável sem inventar identidade.
7. **AC7 — Testes reais do escopo:** testes JUnit 5/Spring Boot Test cobrem o contexto e a resposta HTTP do health check; não há endpoint ou fixture de negócio criado somente para elevar cobertura.
8. **AC8 — Limite de escopo:** não são introduzidas entidades, tabelas, repositórios ou migrações de domínio.
9. **AC9 — Reprodutibilidade:** a evidência local inclui JDK usado, versão do Spring Boot fixada e resultado de `./mvnw -B verify`; sucesso remoto de CI não é alegado nesta story.

## Dev Notes

- **Expected source locations:** `pom.xml`; Maven Wrapper files (`mvnw`, `.mvn/wrapper/`); application code under `src/main/java/<base-package>/`; tests under the corresponding `src/test/java/<base-package>/`. The actual package root is not prescribed by the architecture and must not introduce empty business modules.
- **Estrutura lógica aprovada:** API → aplicação → domínio/portas; a infraestrutura implementa portas consumidas pela aplicação. Domínio não depende de Spring, HTTP ou persistência. DTOs pertencem à API quando houver contrato; entidades JPA não são expostas pela API.
- **Limite do scaffold:** as fontes não definem nomes de pacotes Java nem autorizam criar módulos funcionais vazios. O executor deve manter a estrutura mínima necessária e documentar qualquer decisão de nomenclatura que seja necessária para compilar.
- **Configuração externa:** não versionar valores de credenciais nem gravar segredos em logs. A configuração da conexão PostgreSQL será entregue na Story 1.2.
- **Health check:** responde somente o estado técnico necessário; não inclui endpoint de disponibilidade de negócio.
- **Identidade:** ADR-005 não autoriza inventar provisionamento, cadastro, login ou provedor de identidade. A story não implementa autenticação.
- **Fontes configuradas do AIOX:** `core-config.yaml` aponta para documentos de framework/arquitetura sharded que não existem neste repositório. Foram consultadas as fontes reais em `docs/arquitetura.md`, `docs/arquitetura-checklist.md`, `docs/adr/` e `docs/rtm.md`; não inferir convenções adicionais de arquivos ausentes.

### Testing

- **Frameworks aprovados:** JUnit 5 e Spring Boot Test; MockMvc para a verificação HTTP da API técnica.
- **Localização:** testes no source tree convencional do Maven, sob `src/test/java`, no pacote correspondente ao código de produção.
- **Cenários obrigatórios:** inicialização do contexto; resposta de sucesso e estado `UP` do health check; resposta sem dados sensíveis.
- **Execução:** `./mvnw -B verify` com JDK 21. PostgreSQL/Testcontainers não é critério desta story e entra na 1.2.
- **Limites:** teste de contexto não prova integração com PostgreSQL, CI remota, autenticação, autorização ou regras de negócio.
